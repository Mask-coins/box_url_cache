# 構成と決定事項

更新日: 2026-10-28

## 決定済みの方針

- URLアクセス用のライブラリは、`box_cache` とは別のプロジェクト `box_url_cache` として開発する。
- 保存・読み出しには、依存ライブラリとして `box_cache` を利用する。
- プロジェクト名とURLを受け取り、キャッシュがあれば返す。なければURLにアクセスし、結果を `box_cache` に保存して返すことを基本動作とする。
- 通信、キャッシュを使うかの判断、再取得、HTTPレスポンスやエラーの扱いは `box_url_cache` が担当する。
- 保存機能の不具合や汎用的な改善が必要になった場合は、原因を調べたうえで `box_cache` 側で対応する。
- 利用者向けのREADMEと開発ドキュメントを分け、後者は `docs/` に置く。
- `box_cache` は公開READMEのpip手順で既存の `.venv` にインストールし、キャッシュ保存先は例示どおり `C:\Data\box_cache` とする。2026-10-28に実施済み。

依存先: https://github.com/Mask-coins/box_cache

## 依存先で確認した仕様

2026-10-28に、コミット `d84bc64460967bdd381dd3423fe79557beb1aef1` の公開APIと実装を確認した。以下はその時点の仕様であり、依存先の更新時には再確認する。

- Windows専用、Python 3.11以降に対応する。
- `box_cache.put(project, key, data)` は `str` または `bytes` を新しい版として保存する。
- `box_cache.get(project, key)` は最新版を保存時の型で返す。未登録・破損時は `None` を返す。
- 空文字・空のバイト列も有効なので、存在確認には `is not None` を使う。
- キーにはURLを含む任意のPython文字列を使える。プロジェクト名にはWindowsのファイル名に関する制約がある。
- 再保存しても過去の版を残す。有効期限、容量制限、自動削除、過去の版を指定して読む公開APIはない。
- `get()` は保存日時などのメタデータを返さない。
- 設定・アクセス権・競合などの問題は `CacheError` の派生例外となる。単純なキャッシュ未登録と区別する必要がある。
- 同じプロジェクト・キー・ミリ秒での保存は衝突となり、同時アクセスの競合時も待機せず停止する。
- 保存先は `box_cache` の初期設定が必要。未設定時の自動保存先はない。

## box_cache 0.2.0の更新確認

2026-10-28にコミット `a6825395406a0069d29687bb11b846be675a7f54` のREADME、実装、付加情報のテストコードを確認した。上記の旧版確認に対して、次の公開機能が追加されている。

- `put(project, key, data, *, attributes=None)` で本文と付加情報を同じ版として保存できる。
- `get_with_attributes(project, key)` で同じ最新版の `(本文, 付加情報の辞書)` を一括取得できる。未登録・破損時は `None`。
- 付加情報にはJSON互換の辞書を渡す。ファイルへの変換と復元は `box_cache` が担当し、管理用メタデータとは分離される。
- 従来の `get()` は本文のみを返す。付加情報のない旧キャッシュは、新APIで付加情報 `{}` として取得できる。
- 付加情報の項目の意味と変更時の互換性は、呼び出し側が管理する。基盤側の保存日時は、このAPIでも公開されない。

これにより、本文とHTTP関連情報を独自のファイル形式にまとめる必要がなくなった。現時点の設計案は、本文を `bytes`、HTTP関連情報を `attributes` として基盤に渡す構成とする。項目の追加時の既定値や意味の変更への対応は、引き続き本ライブラリで設計する必要がある。

公開コードとテストコードの確認であり、最新版の再インストールやテストの実行は行っていない。既存venvに前回インストールした版は0.1.0。

参照: [更新コミット](https://github.com/Mask-coins/box_cache/commit/a6825395406a0069d29687bb11b846be675a7f54)

## 基本動作（決定済み）

このライブラリは、URLを使った外部リソースへのアクセス結果をキャッシュし、呼び出し元へ返す。

1. 呼び出し元からプロジェクト名とURLを受け取る。
2. `<ユーザー指定プロジェクト名>_200` を保存先プロジェクト名、URLをキーとして `box_cache` から読み出す。
3. 正常なキャッシュがある場合は、それを返す。
4. キャッシュがない場合は、URLへアクセスして結果を取得する。
5. HTTPレスポンスは `<ユーザー指定プロジェクト名>_<ステータスコード>` に保存する。正常結果と異常結果は同じ保存先や正常リターンに混在させない。異常時の通知方法は詳細設計で決める。

通常の呼び出しはキャッシュの利用を優先し、毎回のアクセス履歴の蓄積を目的として通信するものではない。
公開関数名、戻り値の型、成功・失敗の定義などの詳細は、以下の提案・未決定事項として扱う。

## ステータス別の保存と異常制御

会話で確認した方針:

- `my_project` の200の応答は `my_project_200`、404は `my_project_404`、500は `my_project_500` に、URLをキーとして保存する。
- 通常の読み出しでは `my_project_200` を探す。異常結果のキャッシュを正常結果として返さない。
- 異常結果の保存によって、保存済みの200の結果を覆わない。
- 異常の種類ごとに呼び出し側から制御できる余地を残す。具体的なAPIと既定動作は未決定。

異常制御の設計案（未確定）:

- HTTPステータスごとに、異常キャッシュを使って通信を抑止するか、再試行するかを指定できるようにする。異常キャッシュを使う場合も、異常として通知する。
- 異常キャッシュを再利用するなら有効期間を設けられるようにし、失敗状態を無期限に固定しない。
- 再試行の回数と待機時間には上限を設ける。
- 既定では異常キャッシュを再利用せず、自動再試行もせず、HTTP異常を例外として通知する案とする。
- タイムアウト・接続失敗などHTTPステータスのない異常は、HTTPステータス別の保存・制御とは分ける。保存先の名前と保存内容は未決定。
- キャッシュ基盤の読み出し・保存失敗も通信異常とは区別する。HTTP異常と保存失敗が重なった場合に、元のHTTP異常を失わない通知方法を検討する。

## 提案中の初期仕様

以下は会話中の提案であり、まだ確定した仕様や実装済みの機能ではない。

- 公開APIは `box_url_cache.get(project, url)` を基本とする。
- 初期版はHTTP/HTTPSのGETを対象とし、呼び出し元が指定する認証・Cookie・リクエストヘッダーへの対応範囲は別途決める。
- キャッシュの有無によらず、同じ型の結果オブジェクトを返す。本文はバイト列として保持し、必要に応じて呼び出し側で文字列に変換する。
- 結果オブジェクトには本文・ステータス・ヘッダー・取得日時・最終URLと、キャッシュ由来かどうかを示す情報を持たせる。
- 呼び出し元のプロジェクト名にステータスコードの接尾辞を付け、URLをキーとして使う。接尾辞を含めたWindowsの名前・長さの制約を検証する。URLの加工や他用途との名前の衝突回避は別途決める。
- 通信失敗・HTTPエラー・保存失敗の扱いは明示的に定める。案として、正常に取得し保存できた場合に結果を返し、それ以外は例外とする。
- 明示的な再取得を指定すると、キャッシュがあっても通信する。
- 本文を `bytes`、ステータス・ヘッダー・取得日時・最終URLを `attributes` として同時に保存する。読み出しには `get_with_attributes()` を使い、独自のファイル化形式は設けない（0.2.0を踏まえた改訂案）。
- 将来の有効期限の判断に備え、取得日時は `box_url_cache` の保存データに含める。

## 未決定事項

- 公開API、HTTPクライアント、タイムアウト、対象とするHTTPメソッド。
- キャッシュキーの構成。URL以外にリクエストヘッダーなどを含める条件。
- HTTP異常や通信失敗時の例外・制御API、異常キャッシュの再利用条件、HTTPステータスのない異常の保存方針。
- `box_cache` が破損として `None` を返した場合の再取得、および本ライブラリの保存形式に合わないデータを読み出した場合の扱い。
- リダイレクト、URLの同一性、リクエスト条件の違い、別用途で同じプロジェクト名とキーを使った場合の扱い。
- 付加情報の項目・スキーマ互換性、有効期限、依存先のバージョン固定方法。
